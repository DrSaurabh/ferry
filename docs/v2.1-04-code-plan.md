Implements `v2.1-02-design.md` **rev 1** (§0–§12 as amended by **§13 M1–M25, which override**) for `v2.1-01-requirements.md` **rev 3**, under `docs/handoff/VISION.md` (V1–V13). Inherits everything in `v2-04-code-plan.md` (rev 2, "the 2.0 plan") that this file does not change. Hands-free decisions: **[H#]** (`v2-decisions-log.md`), design amendments **[M#]**, decisions taken here **[CP101+]** (§0.2, one line each, for the plan audit).

Written for AI **phase agents**: each implements one phase (§3) on its own phase branch, CI green, then fast-forwards `main`. Keep this plan and the design open side by side: the plan says *where* and *in what order*; the design (§/M numbers) says *what*. Anything not verified against code or a platform fact is marked **uncertain**; the phase that meets it decides and records the result.

## 0. Ground rules

### 0.1 How agents work (inherited, with 2.1 changes)
- **Inherited unchanged from the 2.0 plan §0.1** and `docs/agents/phase-brief.md`: Python runs locally (`cd pc && python3 -m pytest -q`, `python3 -m pytest -q android/ci`, and now `python3 -m pytest -q tools`), Kotlin compiles only on GitHub Actions; phase branch from current `origin/main`; small compile-safe pushes; emulator suites on a branch only with `[emu]`, `[emu:phone]`, `[emu:tv]`, `[emu:api25]` in the head commit message; a phase is **done** when the branch is green incl. every emulator suite it touches, `main` is fast-forwarded to it, and that `main` run is green with a verified (non-`-UNVERIFIED`) zip; never weaken a test; never push fix-ups straight to `main`; never rename `android.yml`; `:core` has no `android.*` imports; no dependency beyond §0.3 without a decisions-log row. Wait for CI with `docs/agents/ci.sh` (`gh api`, not `gh run watch`).
- **Phase ids** are **Ph11–Ph19** (continuing 2.0's Ph0a–Ph10; "P11–P14" are requirements) [CP101]. Branch = `ph11` … `ph19`. Commit messages start with the phase id (`Ph13: picker back + discard dialog`).
- **Records** [CP102]: progress lines in **`docs/v2.1-progress.md`** (`Ph13 · step · commit · run id · what is left`), build log in **`docs/v2.1-06-build-log.md`** (one section per phase; build decisions numbered **B101+**). Carry-over notes for later phases go to `docs/agents/carry-notes.md` under a "2.1" heading.
- **Snapshots** [CP103]: tag pushes are refused by the proxy. Before Ph11 starts the coordinator pushes branch `snapshot/v2.0-final` (= current `main`); each phase agent pushes `snapshot/pre-ph1N` from `main` before its first commit only if the coordinator asks. Branch deletion is also refused: leave phase and snapshot branches on the remote.
- **Read order for a phase agent**: `v2.1-audit-brief.md` (non-goals) → this plan §0, §2, its phase in §3 → the design sections named there **plus every M amendment named** → the files listed. Do not read the whole 2.0 plan; its §4.14 (instrumented test conventions) and §5.2 (CI) are the parts most often needed.
- **Logging is part of every feature** (V11): from Ph11 on, every new clickable passes a tap id, every new screen logs `screen`, every user-visible error goes through `err.shown`, and every new intent has its row in `docs/v2.1-log-events.md` *in the same phase*. The tap-id lint test (Ph11) enforces the first rule.
- **2.0 regression rule**: existing tests stay green. A test may be *adapted* only where 2.1 deliberately changes the behaviour it checks (named per phase, e.g. `CastLoopbackTest`, `PhoneScreenshotTour` for the TV button [M25-C3]; `ShareLocationAllowTest` → `ShareOriginalTest`; `test_removed_routes.py` [M11]); the phase's build-log section lists each adapted test and why.
- **Strings**: all new user-visible text in `res/values/strings.xml` (phone/TV) or a module constant in `ferry.py`; wording exactly as the design/M text where it is quoted.

### 2.1 `docs/v2.1-log-events.md` — written FIRST (Ph11 step 1) [CP107, M18, M25-C13]
Three machine-readable parts, each a markdown table between HTML comment markers so `tools/review_logs.py` and the JVM test `EventCatalogueTest` (reads the file via a Gradle test resource path `../../docs/v2.1-log-events.md`) parse the same file:
1. `<!-- events:start -->` … `<!-- events:end -->`: `| event | layouts | fields | level |` — every event name of design §7.1 + M18 (`app.start` (`ver`, `api`, `exit`, `tz`), `app.stop/fg/bg`, `screen`, `tap`, `key` (`code`, `src`), `back`, `perm` (`name`, `ask|result`), `pick`, `dialog` (`name`, `choice`), `notif`, `send.start/item/wait/queued/resume/done/cancel`, `share.resolve`, `svc.start/stop` (`reason`), `lock`, `disc` (`target`, `result`, `ms`, `retry`), `conn`, `poll.start/stop`, `work.run`, `ctl.tx/ctl.ack` (phone), `ctl.rx` (TV, `result`), `play` (`event`, `pos`, `reason`, `codec`, `size`, `rotation`, `first_frame_ms`, `dropped`), `zoom`, `slide`, `doc`, `caps`, `volume`, `err.shown` (`text`), `wrong` (`screen`, `note`), `clock` (`peer`, `offset_ms`), `device_name` (`src`), `gap`, `diag` (2.0 shim)). `level` = N (Normal) or D (Detailed only).
2. `<!-- outcomes:start -->` … `<!-- outcomes:end -->`: `| id | intent | outcome | within_s | key |` — e.g. `O1 | tap id=send | send.start\|err.shown | 5 | -`; `O2 | send.start | send.done\|send.wait\|send.queued\|send.cancel | - | batch`; `O3 | ctl.tx | ctl.ack | 3 | id`; `O4 | ctl.tx | ctl.rx(TV) | 3 | id`; `O5 | tap id=tv | screen name=controller | 2 | -`; `O6 | tap id=cast | play event=first_frame\|err.shown | 15 | -`; `O7 | perm ask | perm result | 120 | name`; `O8 | dialog shown | dialog choice | 300 | name`; `O9 | work.run found=yes | send.resume\|notif name=tap_to_send | 30 | -`. Intent/outcome syntax: `event [field=value]…`, alternatives with `|` (escaped `\|` in the table), `(TV)`/`(PC)` = the line must come from that device kind; `key` = the field that correlates the pair (`-` = next matching line of the same device).
3. `<!-- signals:start -->` … `<!-- signals:end -->`: `| rule | L6 text | parameters |` — **G1** intent without outcome (catalogue part 2); **G2** same tap id ≥ 3× within 5 s; **G3** screen A→B→A within 10 s; **G4** same `dialog`/`err.shown` twice in a row; **G5** `back result=discarded_picks`; **G6** `app.bg`/`app.start exit≠user` while a `send.start` or `play` is open; **G7** `play event=stop|back` < 10 s after first frame; **G8** `send.wait` lasting > 30 s; **G9** = O3/O4 failures; **G10** `perm result=denied`; **G11** every `wrong` with ±30 s context.
Each phase that adds an intent adds its row in part 2 in the same commit; `EventCatalogueTest` fails if a tap id used in code (collected by `TapIdLintTest`) has no event or outcome row where the catalogue marks it `required` (column `notes` in part 1 may say `tap ids: send, tv, cast, done, …`).

### 2.2 Event line format (phone and TV) [§7.1]
```
2026-11-24 02:01:03.456 #1234 s=7f3a tap id=send screen=picker
2026-11-24 02:01:03.512 #1235 s=7f3a err.shown text="PC not found — is Ferry running on the PC?"
```
- Local time `yyyy-MM-dd HH:mm:ss.SSS` (`app.start` carries `tz=+05:30`); `#seq` monotonic across restarts (CP109); `s=` 4-hex session id per process start; event name `[a-z][a-z0-9_.]*`; fields `key=value`, value quoted when it contains space, `"`, `=` or is empty; `"`→`\"`, `\`→`\\`, newline→`\n`; ≤ 2 KB per line (truncate value with `…`). No photo content; file names allowed (L1).
- File `files/ferry-app-log.txt` (+ `.1.txt`), rotate at 2.5 MB (≤ 5 MB). The PC's own lines keep their 2.0 `RequestLog` format; `review_logs.py` parses both.

### 2.3 `POST /api/v1/logs` (phone/TV → PC) [§7.2, M8, M12]
- Request headers: `X-Ferry-Device` (name, existing), **`X-Ferry-Device-Id`** (4 hex, CP126), **`X-Ferry-Device-Type`** (`phone`|`tv`), **`X-Ferry-Log-From`** (first `seq` in the body), `Content-Type: text/plain; charset=utf-8`. Body: whole lines, ≤ 512 KB, ends with `\n`.
- Replies: 200 `{"ok":true,"stored":N,"last_seq":S,"time_ms":T}` (lines with `seq ≤` stored last are dropped and not counted); 413 body too big; 400 not UTF-8 / no newline; **404 from a 2.0 PC** → app stops shipping for this process. `time_ms` → app logs `clock peer=pc offset_ms=` (also from `/api/v1/info`).
- Folder: `<data-dir>/logs/<sanitize_name("<name> (<id>)")>/app-log.txt` (`unknown/` without id); `.last-seq` beside it.
- App side cursor: `shippedSeq` advances to the reply's `last_seq` only.
- All app requests also carry `X-Ferry-Device-Id` and `X-Ferry-Device-Type` (interceptor), which the PC uses for M9/C6.

### 2.4 TV control API v2 — `POST /api/v1/control` [§1.1, M6, M13, CP127]
Body = design §1.1 table plus `"id": <phone seq>` on every request. Field names: `action`, `id`, `key` (`up|down|left|right|ok|back|home|menu|rewind|ff`), `position_ms`, `zoom` (`in|out|fit`), `pan_dx`, `pan_dy` (−1…1), `volume` (`up|down|mute|unmute`), `text`, `submit`, `on`, `kind`, `items` (CastItem list), `start`, `source`, plus 2.0's `delta_ms`, `interval_ms`.
- Answers: 200 `{"ok":true,"result":"applied"}`; 409 `{"result":"ignored","why":"<no_player|not_zoomable|no_text_field|volume_fixed|not_foreground>"}`; 400 unknown action / missing field (2.0 TVs answer 400 to new actions → phone shows the old-TV message, M25-C10).
- TV logs `ctl.rx id= action= result=`; phone logs `ctl.tx id= action=` and `ctl.ack id= ms= result=`. State polls are **not** logged except on change or failure (M8).
- `POST /api/v1/cast`: `kind` adds `document`; `source` default `phone`.

### 2.5 TV state v2 — `GET /api/v1/state` [§1.3, M13, M16, M18]
JSON exactly as design §1.3, plus `"time_ms"`; `volume` may be `null` (fixed volume); `app` = `BuildConfig.VERSION_NAME` (M25-C8); `device` = `DeviceNames` TV chain (M25-C15). Kotlin model `TvStateV2` in `:core` with every field defaulted, `api` default **1** (missing = 2.0 TV); `CastState` (2.0) is a subset of the same JSON, so a 2.0 phone keeps reading a 2.1 TV.

### 2.6 Send queue — `files/send-queue.json` [§5.4, M1, M5]
```json
{ "schema": 1, "created_ms": 1764000000000, "batch": "3f2a",
  "pc": {"id": "<pc id from /info>", "name": "Saurabhs-PC", "address": "192.168.1.20:8765"},
  "items": [ {"name":"IMG_1.jpg","size":4200000,"mtime_ms":1764,"original":true,
              "ref":"media:1234" | "copy:pending/3f2a-0-IMG_1.jpg" | "uri:content://…",
              "mime":"image/jpeg","meta":{"taken":"2025-11-03 10:15:00","gps":"yes"},
              "state":"todo" | "share_again" } ] }
```
Written atomically (tmp + rename) at send start, after each finished item, at hand-over; deleted when the send finishes or is cancelled. Unknown `schema` → file renamed `send-queue.bad.json`, banner not shown, logged `err` (never crash). `waitingSince` and `checksStopped` live in `Prefs`.

### 2.7 Upload headers and PC readable line [§7.3, L5, M10]
- Phone → PC on `POST /api/v1/upload`: `X-Ferry-Taken: 2025-11-03 10:15:00` (absent if unknown), `X-Ferry-Gps: yes|no|removed|unknown`, `X-Ferry-Original: 1|0`, `X-Ferry-Batch: <id>;<i>;<n>`; on `check-batch`: `X-Ferry-Batch: <id>;0;<n>`. All optional (2.0 phones send none; the PC line then says `taken ?`).
- PC line: `saved IMG_20251103_101500.jpg · 4.2 MB in 0.21 s · 20.0 MB/s · taken 2025-11-03 10:15:00 · GPS yes (phone: yes) · original · from vivo V2413` (for skipped: `already on PC IMG_….jpg · from …`). Batch: `batch 3f2a: 105 files · 102 saved · 3 already on PC · 5.91 GB in 4 min 04 s · 24.3 MB/s`.
