### Decisions
- **B101** `migrate_old_logs(data_dir, note)` returns the folder the request log uses: `logs/`, or the data folder
  itself when a move fails ("keep the old place", one console note). A `logs/ferry-log.txt` that already exists is
  never overwritten (the old file then stays where it was).
- **B102** `DeviceLogStore`: device id must be 1–16 hex chars, otherwise `unknown/`; folder = `sanitize_name("<name>
  (<id>)", dest_dir=logs)` and must resolve directly under `logs/` (else `unknown/`). Lines whose `#seq` ≤ the stored
  last are dropped; lines without a seq (e.g. `gap`) are kept unless `X-Ferry-Log-From` ≤ last (a repeated body).
  Cap sweep: rotated files (`*.1.*`) oldest first, then other devices' current files; never `*.zip`, `ferry-log.txt`,
  `.last-seq` or the file just written.
- **B103** `POST /api/v1/logs` answers 400 to an empty body (no newline), 411 without Content-Length (same as
  check-batch); request-log outcome `log N lines`; no console line (would be noise every 10 min).
- **B104** `verify_inbox.py device-log` takes `--logs <PC data>/logs --expect ev1,ev2 [--device substr]`; the suite
  helper is `check_device_log <PC> <events>` (the plan's `--pc T` wording maps to this helper).

  catalogue's three tables parse (same split rule as `EventCatalogueTest`).
- Step 2 (`:core`): `log/EventLog.kt` (+ `Detail`), `log/LogStateStore.kt`, `log/LogReader.kt` (+ `LogChunk`),

- **B106** `RingLog` stays unchanged in Ph11a (the app still writes through it until Ph11b swaps in `EventLog`;
  its tests stay). Ph11b decides whether to delete it (plan §1.2 "agent's choice").
- **B107** `EventLog` tail (`snapshot()`, PS3): values unescaped; a `diag` line reads `… diag <tag> <msg>` like 2.0's
  `RingLog` line, so 2.0 androidTests such as `SendHelpers.finishedRuns()` (`contains(" engine finished:")`) keep
