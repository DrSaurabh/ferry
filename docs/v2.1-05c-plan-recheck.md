## 2. New findings

### E1 — Medium — Ph17b / §4.7 / Ph17a: Documents row on PC-T breaks `TvLaunchAndFocusTest` (PS7 only half fixed) — V7, V12 (regression rule)
`run_instrumented.sh` seeds PC-T with `notes.txt` (verified l.84); Ph12 makes `.txt` kind `text`; Ph17b adds a Documents row for PDF/txt on the TV home. `TvLaunchAndFocusTest` (verified) lists `notes.txt` in the expected outbox, then presses `down` from Apps and asserts the next row is `other`, then looks for `old.avi` under Other. With a Documents row (holding `notes.txt`) that sits between Apps and Other, `down` from Apps lands on Documents and the test fails; the same class runs in the API 25 suite. §4.7 and Ph17a claim existing TV/API 25 classes are "unchanged", and Ph12 even says "no TV test changes before Ph17b", but Ph17b's list adapts only `TvPcNotFoundTest`, `TvSlideshowTest`, tour. Also H96 makes OK on an Other card show a message; the test asserts "one OK = exactly one click" (probably still fine, uncertain).
Fix: Ph17b lists `TvLaunchAndFocusTest` (TV and API 25 runs) as adapted (Documents row between Apps and Other holds `notes.txt`; navigation adjusted), or seed `notes.txt` into PC-T under a name that stays Other. Correct the "unchanged" sentences.

### E2 — Medium — Ph15 staged job: the host file check can pass with no resume — V1 (proof of the riskiest feature)
`check_waiting_sent A` "polls for the 3 files". Part A shares two `sharehelper` files; `ShareToFerryTest` (earlier in `phone.txt`, verified) already sent files named `ferry-share-big.bin / -notes.txt / -small.bin` (same deterministic content, `ShareActivity.FILES`) to PC-A, and the inbox is never cleared; the second (NoExempt) variant also re-sends what the first variant sent. So the three files exist byte-identical before any resume, and a resumed send takes the "already on the PC" path (queue disappears anyway). Exempt variant is protected by Part B's `work.run found=yes` → `send.resume` log assertion; **NoExemptB is not**: it asserts only "queue file disappears ≤ 60 s", true for a skip-all send, and nothing asserts the tap path really ran.
Fix: a host step that empties or uses a distinct PC-A inbox subset per variant (or distinct file names/sizes in the helper mode), and NoExemptB also asserts `notif name=tap_to_send` and `send.resume` in the app log (catalogue O9 already exists).

### E3 — Medium (timing uncertain) — Ph15: Part A `after` → Part B start races the end of the resumed send
`check_waiting_sent` returns when the files are on the PC; `run_class` for Part B immediately does `am force-stop`. The queue-file delete, `files/pending/` cleanup and `ResumeScheduler.cancel()` happen after the last upload response in the resumed service process. A force-stop in that window leaves the queue/copies/unique work in place and Part B's final-state assertions fail intermittently (a CI-green risk, not a product bug). Window size is uncertain.
Fix: `check_waiting_sent` also waits until the queue file is gone (`run-as app.ferry ls files/` on the debug APK, ≤ 60 s) or until `send.done` appears in the shipped log, before returning.

### E4 — Low — CP136 / §2.1: reverse catalogue check is nearly vacuous
"Every part-1 event appears as `"<name>"` in `src/main`" is satisfied by unrelated quoted words (`"key"`, `"tap"`, `"screen"`, `"back"`, `"play"`, `"doc"`, `"zoom"`, JSON names in models) so forgotten events (the PO1 concern) pass. It also only says `src/main` (of which module?); `gap` is produced as line text by `:core` `LogReader`, never via `event("gap")`. Fix: use the same `event("<name>"` / `detailed("<name>"` pattern as the forward direction over both modules' `src/main`, and list `gap` (and any other non-`event()` producers) in a small allow-list.

### E5 — Low — Ph13 / Ph17a: "About" items ship before the About screen exists (Ph19) — V7, phase self-containment
Design M22 puts "About" in every TV Menu and Ph17a's `TvMenuItemsTest` asserts "items exactly as M22"; Ph13's Settings row adds the About entry. `Screen.About`/the TV About land in Ph19 (`AboutTest`). Between Ph17a and Ph19 `main` has a Menu item that cannot be used (V7). Fix: add a stub About (version + text) in Ph13/Ph17a, or add the item in Ph19 and word the Ph17a test "M22 minus About".

### E6 — Low — Ph17a/b Done: `[emu:api25]` claims nothing in the plan can prove
Done lines say "(TextureView on API 25)" and "(PdfRenderer on API 25)", but no new class is assigned to `api25.txt` in Ph17, and PC-D is "TV suite only" (§4.7) so `PortraitVideoTest`/`PdfViewerTest` have no fixture host on the API 25 run (PC-A + PC-T on 18769). Fix: name the api25 classes and give that suite PC-D (or an equivalent), or drop the claims.

### E7 — Low — Ph18 / CP140: phone → TV documents need a non-MediaStore source; file not listed
The cast file builder in `media/ContentSources.kt` (verified) queries `MediaStore.Images/Video` for name/MIME/size; a SAF URI from `ACTION_OPEN_DOCUMENT` needs `OpenableColumns` and `openFileDescriptor`. `ContentSources.kt` is not in Ph18's file list, and `ControllerTest` feeds a "pushed `report.pdf` URI" without saying which authority. Fix: list `ContentSources.kt` (a document variant of the cast-file builder) in Ph18 and test with a `content://` documents/FileProvider URI.

### E8 — Low — H98 narrows requirement L6 without a requirements note
L6 (rev 3, user-approved) lists "app backgrounded or killed mid-task" as a distress signal; G6/H98 drop backgrounding during a send/cast. I agree with the engineering (designed path, noise), but the phase brief says never change agreed requirements. Fix: add one clarifying sentence to the requirements L6 row (or flag in the user's morning summary), not just the decisions log.

### E9 — Low — `android.yml` path filter not extended (verified)
`android.yml` runs on `android/**`, `pc/**`, itself. The plan adds `tools/**` and `docs/v2.1-log-events.md` only to `pc.yml`. `EventCatalogueTest` (in `app-build`) is not triggered by catalogue edits, and guide/tool-only commits (`docs/guide/**`, `tools/**`, `LICENSE`) do not rebuild `package`/`dist`. Fix: Ph11a adds `tools/**`, `docs/v2.1-log-events.md`, `docs/guide/**`, `LICENSE` to `android.yml` paths.

### E10 — Low — small ownership gaps
(a) `verify_inbox.py device-log` has no owner in §1.6 ("Ph11a (paths), Ph12, Ph15"), but Ph11b's `LogShippingTest` and TV host check use it; §4.3 puts it in Ph11a. (b) `SetupFlowTest` "last in `phone.txt`" is stated only in CP142/Ph13; later phases (Ph14–Ph19) that add lines need "insert before `SetupFlowTest`". (c) Ph19's `guide-setup-n.png` shots have no producing class: `PhonePermissionTour`/`PhoneScreenshotTour` start with `welcomeDone=true` (verified), so only `SetupFlowTest` can shoot setup; name it as the shooter. (d) `push_fixture NAME` is listed in §1.6 but no phase uses it (drop).

### E11 — Low — rule 12: staged job size
Four classes (`PartA/B`, `NoExemptA/B`), eight host functions, two debug hooks. Justified by PS1 and by the riskiest feature; only trim `push_fixture` (E10d) and consider asserting Part B/NoExemptB's in-app state from the host (`run-as … cat files/ferry-app-log.txt`) rather than two extra instrumentation classes (which also removes E3). No other over-engineering found: `PhoneTopBar`, PC-D, `PENDING` set, the single shipper rule and the "Facts to check" list are proportionate; the rejected parts (second instrumented method, per-item fixtures, SurfaceView switch, Ph18 split) were the right rejections.

### E12 — Low — doc nits
(a) §0.3: the `androidx.media:media` row is separated from the table by a blank line (renders as a stray table). (b) Plan §0.1 `pytest -q tools` vs brief `pytest -q tools/tests`. (c) CP115 says "on the runtime classpath via `media3-ui`": a runtime-only transitive is not on the compile classpath, so the "only if missing" check can mislead; declare it explicitly (uncertain: which scope media3-ui 1.5.1 publishes). (d) Design §12 line 165 still promises a TextureView "fallback switch" while PO16(d) was rejected; add a half-line to §14. (e) CP121 does not list the broken PDF that CP135 uses.
