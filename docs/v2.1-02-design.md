# Ferry 2.1 (Stage A) — Design (A2, 2026-11-24, rev 0)

Implements `v2.1-01-requirements.md` rev 0 on top of the 2.0 design (`v2-02-design.md`). Governing: `VISION.md` (V1–V13). Decisions marked **[H]** go to `v2-decisions-log.md` (H61+).

## 0. Overview of changes
```
 Phone app                                   Fire TV app                         PC program (stdlib)
 ─ Controller screen (replaces Remote)  ──▶  TV control API v2 (port 8766)      ─ /tv, /app redirect, /guide
   touch pad, playback, slideshow, zoom,       key injection, seek_to, zoom,    ─ /api/v1/logs (device logs)
   volume, text, Browse (PC outbox/phone)      volume, text, open (PC items),   ─ readable log lines + EXIF
 ─ Send queue survives (P13/P14)                state v2 (screen, caps, …)       ─ QR only until 1st phone; keys A, Z
 ─ Picker/back fixes, permissions setup      ─ Zoom/pan (photos, PDF, video)    ─ outbox kind "document"
 ─ Share → original fix (B2)                 ─ PDF/txt viewer                   ─ About, LICENSE
 ─ Preview, thumbnails, Done, U4             ─ TextureView player (B3)
 ─ EventLog + LogShipper (both layouts) ──────────────────────────────────────▶ logs\<device>\
```
No new third-party libraries [H61]: Media3, Coil, OkHttp, WorkManager (AndroidX — **new dependency, AndroidX only**, needed for P13), Compose stay.

## 1. TV control API v2 (R1–R11, T7–T11, U7)
Same server `CastReceiverServer` (TCP 8766), same three endpoints; bodies extended (JSON lenient both ways: `ignoreUnknownKeys`, so 2.0 phones keep working with 2.1 TVs).

### 1.1 `POST /api/v1/control` — actions
| action | fields | needs | TV effect |
|---|---|---|---|
| existing: toggle, play, pause, next, prev, seek (delta_ms), stop, interval | — | a cast or player/viewer on screen | as 2.0, now also for **outbox** player/viewer (not only casts) |
| `key` | `key`: up/down/left/right/ok/back/home/menu | Ferry in foreground | **injected KeyEvent** (down+up) into the TV activity → identical to the remote everywhere in Ferry [H62] |
| `seek_to` | `position_ms` | video | absolute seek |
| `zoom` | `zoom`: in/out/fit, or `pan_dx`,`pan_dy` (−1…1, fraction of view) | zoomable screen | §3 |
| `volume` | `volume`: up/down/mute | — | `AudioManager.adjustStreamVolume(STREAM_MUSIC, …, 0)` [H54]; no system UI flags |
| `text` | `text`, `submit` (bool) | a registered text field focused | sets the field's value; submit = its IME action |
| `shuffle` | `on` | slideshow | T10 |
| `date_line` | `on` | slideshow/viewer | T10 |
| `open` | `kind` video/photos/document, `items` (as CastItem; URLs point to the **PC outbox**), `start`, `source:"pc"` | — | opens the outbox player/viewer/doc screen on the TV (not a "cast": the phone leaving does not stop it) [H63] |
Unknown action → 400 (old TV answers 400 to new actions → phone shows "Update Ferry on the TV" when `api` < 2).

### 1.2 `POST /api/v1/cast` — extended
`kind` adds `document` (one PDF/txt item from the phone, R7/T8). `source` (default "phone").

### 1.3 `GET /api/v1/state` — v2 (superset of 2.0)
```json
{ "api":2, "app":"2.1.0", "device":"Saurabh's FireTVStick",
  "screen":"home|player|viewer|doc|cast_video|cast_photos|cast_doc|pc_not_found|other",
  "kind":"video|photos|document|idle", "source":"pc|phone|none",
  "title":"…", "index":0, "count":0, "playing":false, "position_ms":0, "duration_ms":0,
  "interval_ms":5000, "shuffle":false, "date_line":false,
  "zoom":{"zoomable":true,"level":1.0}, "volume":{"level":7,"max":15,"muted":false},
  "text_field":{"label":"PC address","value":"192.168.1."} | null,
  "caps":{"avc_max":"1920x1080","hevc_max":"1920x1080","hevc10":false,"vp9_max":null},
  "page":{"n":3,"of":12} | null }
```
Produced by **`TvStateHub`** (new, TV): every TV screen publishes a partial state into it (`publish(screen, fields)`) while visible; `CastSinkImpl.snapshot` becomes one input of the hub. Answered from a @Volatile snapshot (no main-thread blocking, as 2.0).

### 1.4 TV-side plumbing
- **`TvRemoteBridge`** (new): main-thread `activity.dispatchKeyEvent()` for `key`; maps to KEYCODE_DPAD_*, DPAD_CENTER, BACK, HOME → Ferry home screen (not the Fire TV launcher: V12 Level 1 only), MENU.
- **`TvTextTargets`** (new): text fields on TV (today: Enter PC address / Enter TV address) register `{label, value(), set(v), submit()}` while focused.
- Commands that target a screen (seek_to, zoom, shuffle, date_line, interval, playback) go through one `SharedFlow<ControlRequest>` that the **visible** screen collects (cast screens already do; outbox player/viewer/doc now also do) [H64].
- **Decoder caps** (`TvCaps`, new): computed once from `MediaCodecList(REGULAR_CODECS)`: for video/avc, video/hevc, video/x-vnd.on2.vp9 — the largest supported size from `VideoCapabilities` (check 3840×2160, 2560×1440, 1920×1080, 1280×720) and HEVC Main10 profile support. Logged at start (L1).

## 2. Phone controller (R1–R11)
- **Entry**: Home gets a "TV remote" button (shown when a TV was ever found or one is found now). Play on TV, after starting, opens the same screen. `RemoteScreen` is replaced by **`ControllerScreen`**; `CastViewModel` keeps TV finding/choosing; new **`ControllerViewModel`** owns the connection (one `CastClient`).
- **Sync**: while visible, `GET state` every 1 s (as 2.0 remote); hidden → stop polling (P14). On `ON_RESUME` reconnect immediately (R10): try last TV (2 s timeout) → discovery → "TV not found — is Ferry open on the TV?" + Try again.
- **Layout (top → bottom)**: TV name + one-line status ("Playing video_….mp4", "Slideshow 3/41", "Ferry home") · **touch pad** (≈ 45 % height) · Back / Home / Menu row · context card · Volume row (− level +, mute) · "Browse" button.
- **Touch pad** [H65]: swipe ≥ 32 dp → one arrow key (direction by larger axis); hold-swipe repeats every 300 ms; tap → OK; when `zoom.zoomable`: pinch → zoom in/out steps, two-finger drag → pan (`pan_dx/dy` = drag/pad size). Haptic tick per key.
- **Context card** by `screen`:
  - video (player/cast_video): title; **Slider** with mm:ss / mm:ss (drag sends `seek_to` on release; while dragging local thumb only); −10 s, ⏮, ⏯, ⏭, +10 s; Stop.
  - photos (viewer/cast_photos): ⏮ ⏯ ⏭; speed chips 3/5/10 s; Shuffle switch; Date switch.
  - doc: page n/of, ◀ ▶ (= left/right keys), zoom.
  - zoom row (any zoomable): − · Fit · +.
  - text_field ≠ null: an OutlinedTextField prefilled with the TV value; typing sends `text` (debounced 300 ms); IME Done → `text` with submit.
- **Browse sheet** (R7): tabs "PC outbox" (list from the PC via existing `FerryClient` outbox API, grouped Videos / Photos / Documents / Other; photo thumbnails via Coil from the outbox URL with size 128 px; videos/docs icons) and "From this phone" (opens the picker in Play-on-TV mode). Tap → `open` (PC items) or the existing cast flow (phone items). Photos: `open` with all outbox photos and `start` = tapped index.
- **Notification / lock screen** (R9): `CastService` (already foreground while casting from the phone) gets MediaStyle-like actions ⏯, −10, +10, ⏭, ■ via PendingIntents → `ControlRequest`s. For `open` (PC-sourced) sessions started from the controller, `CastService` runs in "follow-only" mode (no file server) for the same notification; it stops when TV state is idle/home or after **10 min with nothing playing** (P14) [H66].
- **Too-big videos** (U7): before casting a video, the phone reads width/height/codec/HDR via `MediaMetadataRetriever` (`METADATA_KEY_VIDEO_WIDTH/HEIGHT/ROTATION`, `COLOR_TRANSFER`, mime) and compares with `caps` from `state`; rows over the limit show "4K — too large for this TV" and need "Play anyway" (allowed).

## 3. Zoom and pan on the TV (T7, R8)
- **`ZoomState`** (shared, Compose): scale ∈ {1, 1.5, 2, 3, 4}, offset clamped so the content edge never leaves the screen; `fit()` resets. Applied with `Modifier.graphicsLayer(scaleX, scaleY, translationX, translationY)` to: the Coil image (viewer), the PDF page bitmap, and the **video view**.
- **Video**: the player view switches to **TextureView** (`PlayerView` inflated from `res/layout/tv_player_view.xml` with `app:surface_type="texture_view"`) [H67]. Effects: (a) Media3 applies the rotation tag itself → **portrait videos upright (B3)**; (b) graphicsLayer scaling of the AndroidView works (SurfaceView doesn't scale). Same for the phone preview (P12). Cost: slightly more GPU; acceptable at ≤ 1080p output on the 1st-gen stick (logged: dropped frames via `AnalyticsListener.onDroppedVideoFrames`).
- **Remote mapping** [H68]: **Menu (☰)** opens a small overlay on viewer/player/doc: *Zoom*, *Slideshow speed*, *Shuffle*, *Date*, *Something's wrong*, *About*. Choosing Zoom enters **zoom mode** (badge "Zoom 2× — arrows move, ⏪/⏩ zoom, OK fit, Back done"): ↑↓←→ pan by 15 % of the view, Rewind/Fast-forward = zoom out/in, OK = fit, Back leaves zoom mode (keeps the zoom). Outside zoom mode keys behave as in 2.0. No long-press gestures (Fire OS long-press is unreliable).
- Slideshow: entering zoom (by remote or phone) pauses it (R10); next/prev photo resets zoom to 1. Video: zoom persists until fit/Back-out of the player; playback continues.

## 4. Documents on the TV (T8)
- PC `file_kind`: `.pdf` → "pdf", `.txt` → "text" (else unchanged); TV home gains a **Documents** row (between Photos and Apps).
- **`TvDocScreen`**: downloads the file to `cacheDir/docs/` (≤ 100 MB; larger → "Too large to show on the TV") then: PDF via `android.graphics.pdf.PdfRenderer` (API 21+), page rendered to a bitmap at 2× screen width (memory cap: one page + neighbours, recycled); ←/→ page, ↑/↓ scroll when zoomed or page taller than screen; "3 / 12" badge. Encrypted/broken PDF → "This PDF can't be shown on the TV". TXT: UTF-8 (fallback ISO-8859-1), first 1 MB, 28 sp, LazyColumn, ↑/↓ scroll by a screen.
- Cast `document` from the phone streams from `CastFileServer` the same way.

## 5. Phone: sending (B1, B2, U1–U4, U9, P11–P14)
### 5.1 Back everywhere (B1, U1)
- All phone top-bar Back buttons call `LocalOnBackPressedDispatcherOwner.current.onBackPressedDispatcher.onBackPressed()` — the **same path as the system Back** [H69], so each screen's `BackHandler` decides (picker: album → album list → leave). Albums tab inside an album → list.
- Leaving the picker with picks → dialog "Discard 7 picks?" (Discard / Keep picking) [H59]. Transfer screen during a send: Back goes Home, the send continues (notification) — never cancels.
- Test `BackEverywhereTest`: visits every phone screen, presses top Back and system Back, asserts the landing screen and that picks survive.

### 5.2 Share sends originals (B2) [H70]
`UploadItemFactory.fromShared(uri)`:
1. `content://media/…` → MediaStore id via `ContentUris.parseId`; build canonical `Images/Video.Media.EXTERNAL_CONTENT_URI/<id>`.
2. Other authority (e.g. vivo gallery FileProvider, picker, documents): `MediaStore.getMediaUri()` (API 29+, documents) → else **match by DISPLAY_NAME + SIZE** in MediaStore Images/Video (exactly one row → canonical URI).
3. Canonical URI → `setRequireOriginal` (needs ACCESS_MEDIA_LOCATION, granted at setup) → original bytes.
4. Not resolvable → send the shared stream as is. **No location question when the permission is granted.** The phone checks the sent bytes' EXIF (ExifInterface on the stream; JPEG/HEIC) and the row says "Sent without location — the sharing app removed it. Ferry's own picker keeps it." if GPS absent but the item is a camera photo. (Supersedes the requirement's dialog: a note is less interruptive and nothing is lost — B2 wording updated.)
5. Permission **not** granted (user refused at setup) → the 2.0 location question stays.
Logged: URI scheme/authority/path shape (`content://com.vivo.gallery.fileprovider/…/#####`), which step resolved it, exceptions.

### 5.3 Transfer screen (U3, U4, P11)
- Rows get a 48 dp **thumbnail** (Coil; MediaStore thumbnail for media, icon for others).
- Finished: title **"Done — 4 sent to Saurabhs-PC"** (+ "· 3 already on the PC"), primary **Done** button → Home; notification text the same.
- Send anyway: per item once; after it, an identical re-send shows "Identical copy already on the PC" (final) [U4].

### 5.4 Sends wait for the PC (P13, P14) [H52, H53]
- **`SendQueueStore`** (new, `files/send-queue.json`): items still to send `{name, size, mtime, original, ref: media:<id> | copy:<path> | uri:<uri>}`, target PC (id, name, last address), created time. Written on send start and after each item; deleted when the send finishes or is cancelled.
- `UploadEngine` already has `Phase.WaitingForPc` (P6). New: `TransferService` keeps waiting in the foreground for **10 min**; then (a) shared items with `uri:` refs are **copied** into `files/pending/` if free space > item size + 500 MB (else marked "Share again when the PC is on"), (b) the queue is saved, (c) **WorkManager** unique work `ferry-resume-send` is enqueued: periodic 15 min + one-time with `NetworkType.CONNECTED`, `requiresBatteryNotLow`, (d) the service stops and the notification becomes a quiet "Waiting for Saurabhs-PC — will send when Ferry is running there · Cancel".
- **`ResumeSendWorker`**: Wi-Fi check → quick PC locate (remembered address, then one 2.6 s discovery) → found: start `TransferService` with the saved queue. Android 12+ forbids starting a foreground service from the background **unless the app is exempt from battery optimisation** (asked at setup, U2) → with exemption: start and send; without: post "Saurabhs-PC is back — tap to send" (tap starts it) [H71]. Not found: nothing (next run).
- Phone restart: `RECEIVE_BOOT_COMPLETED` not needed — WorkManager reschedules itself.
- Cancel: notification action and Home banner "1 send waiting for Saurabhs-PC · Cancel".

### 5.5 Setup and permissions (U2, U9)
- **Welcome** becomes a 4-step setup (one screen each, big button, "Skip" small): (1) Photos & videos + location (one system dialog sequence), (2) Notifications (13+), (3) Battery: "Let Ferry work with the screen off" → `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` (already in manifest), (4) Updates: "Allow Ferry to install its updates" → `ACTION_MANAGE_UNKNOWN_APP_SOURCES` (Android 8+). Then Home. Each result logged.
- Afterwards: no permission dialogs; a refused permission shows a one-line banner on the screen that needs it with **Fix** (opens the app's Settings page). Supersedes H23/H47 [H72].
- vivo lock step (U9): removed from setup; `StopDecision` already detects "the system stopped Ferry"; only then the Transfer screen shows a card "vivo stopped the send" with the correct steps ("Press ≡ (or swipe up and pause) → tap 'Ferry' above its card → Lock") and an illustration (drawn vector, no vivo screenshot).

### 5.6 Preview (P12)
`PreviewScreen(item)`: video in a TextureView PlayerView (sound on, ±10 s, play/pause), photo with pinch-zoom (`ZoomState` + gestures). Top line: "3840×2160 · 0:42 · HEVC" + U7 warning when a TV's caps are known. Opened from a ▶ badge on video thumbnails and long-press on any picker cell; Back returns to the picker with picks intact.

## 6. TV home without PC (T9)
`TvHomeScreen` shows rows when the PC is found; when not: header "Ready for your phone" + a single row card "PC not found · Try again · Enter address" (focusable) instead of the full-screen `TvPcNotFound` [H73]. The address entry stays (now registered in `TvTextTargets`). Silent retry every 10 s continues (H45).

## 7. Logging (L1–L7)
### 7.1 Event log (phone + TV) — `EventLog` (core, wraps `RingLog`)
- Line: `2026-11-24 02:01:03.456 #1234 s=7f3a EVENT key=value key="two words"` (seq per process; `s` = session id per app start). Events (names fixed, documented in `docs/v2.1-log-events.md`): `app.start/stop/fg/bg`, `screen` (name), `tap` (id), `key` (TV keys), `back` (screen, result), `perm` (name, result), `pick` (count), `send.start/item/wait/resume/done/cancel`, `svc.start/stop`, `lock` (held ms), `disc` (target, result, ms), `conn` (peer, result), `ctl.tx/ctl.rx/ctl.ack` (action, ms), `play` (event, pos, error, codec, size, first_frame_ms, dropped), `zoom`, `slide`, `doc`, `err.shown` (exact text), `wrong` (marker + note).
- **Tap ids**: a small `Modifier.logTap("send")` / wrapper on every clickable (lint check in a unit test: every `Button/IconButton/clickable` in `ui/` passes an id — grep-based test) [H74].
- Detail level: `Prefs.logDetail` Normal | Detailed; **Detailed by default in 2.1** [H55] ("Trial logging" switch in Settings). Normal drops per-frame/per-poll events (`ctl.tx` for state polls, `disc` retries).
- Files: `files/ferry-app-log.txt`, rotate at 2.5 MB ×2 (≤ 5 MB).

### 7.2 Log shipping — `LogShipper`
- When connected to the PC: at app background, after a send finishes, and at most every 10 min while in foreground → `POST /api/v1/logs` (body = new lines since the last acknowledged offset, ≤ 512 KB per request, `X-Ferry-Device`), PC answers `{"ok":true,"stored":N}`; offset persisted. TV ships too. Failure: retry next time; nothing lost while ≤ 5 MB.
### 7.3 PC side (L3, L5, L7)
- `logs\` folder next to ferry.py: `logs\ferry-log.txt` (moved; old path migrated on start), `logs\<safe device name>\app-log.txt` (append; rotate 20 MB ×2); total cap 200 MB (oldest rotated files removed).
- **Readable per-file line** (L5): `saved IMG_20251103_101500.jpg · 4.2 MB in 0.21 s · 20.0 MB/s · taken 2025-11-03 10:15:00 · GPS yes (phone: yes) · original · from vivo V2413` — PC reads JPEG EXIF `DateTimeOriginal` + presence of GPS IFD itself (stdlib `struct`, first 128 KB); for other types it logs what the phone sent in headers `X-Ferry-Taken`, `X-Ferry-Gps` (yes/no/removed), `X-Ferry-Original` (1/0). Mismatch (phone says GPS yes, PC finds none in a JPEG) → `WARNING` line.
- **Batch summary**: phone sends `X-Ferry-Batch: <id>;<i>;<n>`; at the last item (or 60 s idle) PC logs `batch 3f2a: 105 files · 102 saved · 3 already on PC · 5.91 GB in 4 min 04 s · 24.3 MB/s`.
- Console keys (Windows `msvcrt`, stdlib; ignored elsewhere): **A** = show the QR/install addresses again, **Z** = "Zip logs for Claude" → `logs\ferry-logs-YYYYMMDD-HHMM.zip` (zipfile, stdlib), path printed.
### 7.4 Review script (L6) — `tools/review_logs.py` (stdlib)
Input: the zip or folder. Parses all logs (phone/TV event format, PC log), merges by time, prints a report: per-day summary (sends, files, GB, avg speed, casts, controller use), then **signals** — rules R-1…R-11 exactly as L6 lists, each with ±30 s context lines. Unit-tested with synthetic logs (`tools/tests/test_review_logs.py`).

## 8. PC program (B4, U5, U6, A2, A3)
- `GET /tv` → 302 `/app/Ferry.apk`; `GET /app` with a Fire TV user agent (`AFT` in UA, or `Downloader`) → 302 `/app/Ferry.apk`; browsers keep the page.

Startup "Phone can't connect?" block removed; the tip is printed after a device's failed attempt is observed (e.g. a request that fails/aborts) or never [H75].
- `/guide` serves `Ferry-Guide.html` if present next to ferry.py. `/app` page footer and window header carry the About line (A2).
- Version 2.1.0. `file_kind` adds pdf/text (§4).

## 12. Risks
- TextureView performance on the 1st-gen stick (4K files are already refused; 1080p fine) — logged dropped frames; fallback switch in code (constant) if CI/device shows problems.
- Key injection via `dispatchKeyEvent` works only for Ferry's own window (by design: Level 1).
- Background FGS start (Android 12+) depends on battery exemption — fallback notification.
- Matching shared items by name+size could pick a different file with the same name and size: practically only exact duplicates → same bytes; accepted.
